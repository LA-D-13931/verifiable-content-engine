# 线代交互实验台（原型 v0.1）

一个**独立的**线性代数交互实验原型：11 个可拖动的实验，8 个章节。
在画布上直接拖动向量与矩阵的列，用几何直觉理解线性代数。

- **不依赖任何框架、构建工具或第三方库**，双击 `index.html` 即可打开（也可静态托管）。
- 与工作区里的「高等数学学习站 / 线性代数学习站」**没有任何文件往来**，是单独的一个子站。
- 拆解与借鉴来源见工作区根目录的 [`matrixguts_拆解与借鉴方案.md`](../matrixguts_拆解与借鉴方案.md)。

```bash

# 浏览器打开 http://127.0.0.1:8791/index.html
```

| 操作 | 效果 |
|---|---|

| `←` `→` | 上一个 / 下一个实验 |
| `R` | 重置视角 |

## 四、核心设计：数据 / 渲染 / 判题 三层分离

这是能堆出 58 个实验还不失控的唯一原因，也是加实验的成本所在：

```
lab-data.js（这一关画什么、要做什么）
      ↓ 只读
render2d.js / render3d.js  ——  无状态渲染器，对所有实验是同一套代码
interact.js                ——  同一套指针逻辑，按 scene.interact 开关
      ↓ 写入
engine.js                  ——  集中在一个 switch 里的判题器
```

**加一个实验 = 在 `lab-data.js` 里加一段数据**，其余文件一行都不用改。

### 4.1 场景字段表（`scene`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `space` | `'2d'` / `'3d'` | 画布维度 |
| `matrix` | `[[..]]` / `null` | 当前矩阵；`null` 表示本实验不涉及矩阵 |
| `matrixSize` | `2` / `3` | 省略时按 `matrix` 的行数推断 |
| `shape` | `'square'` / `'area'` / `'cube'` | 面积 / 体积可视化的基准形；`area` 用半格方块，避免被变换后的方块完全盖住 |
| `basis` | `bool` | 是否画基向量与列落点（虚线 + 彩色手柄） |
| `tgrid` | `bool`（默认 true） | 是否画「变换后的网格」 |
| `comboPath` | `bool` | 是否画 v = c₁u + c₂w 的组合路径与实时系数 |
| `metric` | `'det'` / `'rank'` / `null` | 右侧面板的指标强调项 |
| `spanView` | `bool` | 画列空间：秩 2 铺一层淡色底，秩 1 画出那条直线，秩 0 只剩原点 |
| `nullView` | `bool` | 画零空间：秩 1 时画出「被压到原点」的那条直线 |
| `basisCoords` | `bool` | 画 v 在新基下的坐标路径与实时读数（基变换课） |
| `numLine` | `{range:[a,b], title}` | 在画布底部画一条水平数轴（点积/对偶课） |
| `oneDim` | `{basis:[x,y], proj}` | 把向量投影到某个 1D 方向上，并在数轴上标出落点 |
| `dotPair` | `{a,b,proj,showCos}` | 画 a·b 的读数、v 在 u 上的投影与直角标记 |
| `cross` | `{colA,colB,label}` | 叉积：2D 画有向面积，3D 画 a×b 向量与平行四边形 |
| `vectors` | `[{id,data,color,label,draggable,dashed,showTransform,transformLabel,lineUp}]` | 场景中的向量 |
| `lines` | `[{a,b,c,label}]` | 直线 ax + by = c（行图像用） |
| `targetPoint` | `{point,label}` | 目标点（画成金色圆环） |
| `interact` | `{clickPlace,dragVectors,dragColumns,orbit}` | 本实验允许的交互 |
| `toolbar` | `[{id,label,action,matrix?,log?}]` | 画布下方的动作按钮 |

### 4.2 判题类型表（`task.check`）

| `check.type` | 参数 | 判什么 |
|---|---|---|
| `vector-at` | `{target,to,tol}` | 某向量是否到达目标点 |
| `av-at` | `{to,tol}` | Av 是否到达目标点 |
| `matrix-col-at` | `{col,to,tol}` | 矩阵第 col 列是否等于目标 |
| `match-matrix` | `{matrix,tol}` | 整个矩阵是否等于目标 |
| `det` | `{op:'eq'\|'lt'\|'gt',value,tol}` | 行列式的大小关系 |
| `rank` | `{value}` | 矩阵的秩 |
| `on-span` | `{op:'in'\|'out',target}` | v 是否落在列空间里（把 v 并成矩阵最后一列比较秩） |
| `vector-angle` | `{a,b,value,tol,unit,unitTol}` | 两向量夹角是否等于目标（可要求都是单位向量） |
| `intercept` | `{tol}` | 行图像：v 是否命中若干条直线的公共交点 |
| `null-space` | `{tol,dir,minCos}` | v 是否被 A 压到原点（零空间） |
| `eigen` | `{value,tol,tolDeg}` | v 与 Av 共线且 λ = (Av·v)/(v·v) 等于目标 |
| `in-basis-matrix` | `{basis,matrix,tol}` | 新基下 P⁻¹AP 是否等于目标矩阵（相似 / 对角化） |
| `in-basis` | `{to,tol}` | v 在新基（矩阵两列）下的坐标是否等于目标 |
| `dot` | `{a,b,op,value,tol}` | 两向量的点积比较 |
| `cross-mag` | `{colA,colB,op,value,tol}` | \|a×b\| 的大小比较 |
| `cross-dir` | `{colA,colB,dir,minCos}` | a×b 的方向是否与给定方向一致 |
| `solve` | `{to,tol}` | 是否 Av = b |
| `collinear` | `{tolDeg}` | v 与 Av 的夹角是否 ≤ tolDeg（特征方向） |
| `choice` | `{correct}` + `options` + `explains` | 概念辨析题 |
| `actions` | `{all,ordered}` | 动作日志是否包含 / 按序包含指定动作 |

所有判定都带**容差**——拖拽不可能像素级精确，这是交互关卡能判题的前提。
吸附规则：屏幕距离 12px 以内自动吸到最近的 0.5 格。

### 4.3 视觉：与线代讲义站共用一套配色体系

实验台的界面配色**不是自己定的**，而是从讲义站的 `theme-tokens.css` 直接读取：

| | 讲义站 | 实验台 |
|---|---|---|
| 主题 | 4 套（霜蓝 / 暖沙 / 竹青 / 墨檀） | **同一套，同名同值** |
| 模式 | 亮 / 暗 / 跟随系统 | **同逻辑**，`data-theme` + `data-mode` 写法一致 |
| 存储 | `advmath.theme.v1` / `advmath.mode.v1` | **同一组键**，偏好互通 |

在讲义站选了「竹青 · 暗色」，打开实验台就是竹青暗色；反过来也一样。

**画布层是实验台特有的。** 画布上要同时区分 6 种数学对象
（主向量 / Av / 第1列 / 第2列 / 第3列 / 目标点），讲义站的界面 token
区分不了这么多语义色，所以另立一组 `--m-*`：

- 亮暗同色相、只调明度，与讲义站的「低饱和」取色思路一致
- 逐组合验证：对画布底色的对比度 ≥ 4.5:1（亮）/ 5.0:1（暗）
- 两两可辨（灰度不撞），避免色觉障碍用户分不清
- 网格线另有「对底色可辨」断言，防止太浅等于没画

这些都不手写，由 `tools/gen-themes.py` 从讲义站 token 推导并断言，
生成 `assets/css/theme-tokens.css`（8 个组合）与 `assets/js/theme-config.js`。
**改了生成器或讲义站配色后忘了重跑，`check-lab.py` 会直接报错。**

> 踩过的两个坑：
> ① 一度用 `color-mix()` 定义派生色，但实测部分浏览器在
> `getComputedStyle` 里**不把它求值**（原样输出字符串），拿到的全是无效值；
> 现在全部**预计算成实色**。
> ② 我在 `:root` 里写过 `--ink: var(--bg)`，而讲义站 token 里 `--ink` 是**正文色**
> ——变量名撞车，导致主按钮文字变成背景色。**不要覆盖讲义站的 token 名。**

### 4.4 辨析题：数据约定 + 界面约定

**数据约定**（`tools/check-lab.py` 强制，违反直接报错）：

1. `options` 与 `explains` 数量一致、一一对应；
2. 正解位置由 `tools/balance-choices.py` **均匀分布到 3 个位置**
   （当前 20 / 19 / 19）——既不能永远在同一个位置，也不能全挤在一处；
3. `explains` 里正解那条以 `✓ 对：` 开头，错误的两条以 `✗ 不对：` 开头，
   校验器要求「以 ✓ 开头的恰好一条，且下标等于 correct」。

**界面约定**（这是本项目的产品原则，`tools/smoke.mjs` 会守着它）：

| 情况 | 行为 |
|---|---|
| 选错 | **只把选的那条标红**；其余选项保持中性，绝不把正确项标出来 |
| 选错 | 只显示「你选的这条为什么错」那一条解释（不显示别条） |
| 选错 | 所有选项仍可点击，并出现「再试一次」按钮；任务**不算完成** |
| 选对 | 这时才把正确项标绿并锁定选项，任务判定通过 |

**版式与状态约定**（踩过坑，写下来免得再犯）：

- 解释与「再试一次」必须排在**该题全部选项之后**。早期实现把它们插在选项循环里，
  结果一条红解释夹在选项中间，把三个选项劈成两半，看起来像两组题。
- 作答用 `App.choices`（**taskId → 选项下标** 的 map），不是单个值。
  同一关可能有多道辨析题（如 2-3），用单个值会导致后一题把前一题的反馈挤掉。

**为什么这么设计**：早期的实现是「点任意一个选项就把正确项标绿」，
等于直接公布答案——用户只要把三个选项挨个点一遍就过关了，
辨析题也就失去了思辨的意义。现在的做法是只给「你这条不对」的反馈，
判断权留给用户，答错可以重试。

### 4.5 工具栏动作表（`scene.toolbar[].action`）

| `action` | 额外参数 | 效果 |
|---|---|---|
| `play-transform` | — | 播放「恒等 → 当前矩阵」的连续变形动画 |
| `play-inverse` | — | 播放「A → A⁻¹」；det = 0 时提示不可逆 |
| `identity` | — | 矩阵归位为单位阵 |
| `preset` | `matrix` | 直接把矩阵设为预设值 |
| `mul-left` | `matrix`, `log` | 矩阵左乘：M ← X·M（表示「先做原来的，再做 X」） |
| `mul-left-inv` | `matrix`, `log` | 左乘给定矩阵的**逆**：M ← X⁻¹·M，用来演示「撤销上一步变换」 |
| `try-inverse` | — | 求逆并应用（A ← A⁻¹） |
| `reveal-eigen` | — | 显示特征方向虚线并提示 λ |
| `toggle-space` | — | 2D ⇄ 3D 切换（矩阵随之升/降维） |

每个动作都会向 `App.actionLog` 写入一条日志，日志名 = `tool.log || tool.action`，
`actions` 型任务就是拿这个日志判定的。

> **硬规矩：被任务依赖的按钮，点了必须写日志。**
> 否则那条任务永远判不过，而界面上完全看不出异常（这是真实踩过的坑，见下）。

## 五、怎么加一个新实验

只需要改 `assets/js/lab-data.js` 一个文件：

```js
{
    id: '2-3', chapter: 2, title: '你的新实验',
    brief: '一句话讲清这个概念，可以用 <strong>加粗</strong> 和 <em>斜体强调</em>。',
    scene: {
        space: '2d', matrix: [[1, 0], [0, 1]], basis: true, tgrid: true, shape: 'square',
        vectors: [{ id: 'v', data: [1, 1], color: COLORS.v, label: 'v',
                    draggable: true, showTransform: true, transformLabel: 'Av' }],
        interact: { dragVectors: true, dragColumns: true }
    },
    tasks: [
        { id: 't1', text: '任务描述',
          check: { type: 'matrix-col-at', col: 0, to: [2, 1], tol: 0.15 } },
        { id: 'q1', text: '辨析：……？',
          options: ['选项 A', '选项 B', '选项 C'],
          // explains 与 options 一一对应；只有正确的那条以「✓ 对：」开头
          explains: ['✗ 不对：A 为什么错', '✓ 对：B 为什么对', '✗ 不对：C 为什么错'],
          check: { type: 'choice', correct: 1 } }
    ],
    hints: ['提示一', '提示二']
}
```

然后跑校验：

```bash
python3 tools/check-lab.py            # 应输出「全部通过 ✓」
python3 tools/balance-choices.py      # 新加的辨析题会被自动摊平到 3 个位置
```

校验脚本会拦住这些常见错误：判题类型拼错、`options` 与 `explains` 数量不一致、
`correct` 下标越界、`actions` 引用了工具栏里不存在的日志名、
矩阵维度与 `space` 不匹配、id 前缀与 `chapter` 不一致、
以及**页面顶栏写的实验总数与实际数据不符**（这条已经真实拦下过一次）。

`check-lab.py` 分两层：

- **结构层**：字段齐全、id 唯一、章节自洽、判题类型在白名单内、目标维度正确、
  `actions` 引用的日志名在工具栏里真实存在、页面顶栏数字与数据一致。
- **教学层**（本轮新增）：
  - **目标可达性穷举**——对每类任务验证目标是否落在可达参数空间里。例如
    `av-at` / `solve` 会检查目标是否在列空间内（用秩比较），不在就直接报错，
    避免出现「怎么拖都过不了」的关卡；
    `rank` 会检查目标值是否超过 `min(行数, 列数)`，以及列不可拖时秩能否改变。
  - **辨析题唯一性**——`options`/`explains` 一一对应、`correct` 下标合法、
    以 `✓` 开头的解释恰好一条且下标等于 `correct`、选项文本不重复。

`verify-actions.mjs` 是第 2 轮新加的第三道校验：它把每个实验的工具栏动作
在真实页面上按顺序跑一遍，检查

- 每个实验**至少有一个 preset 命中** match-matrix 任务的目标
  （其余 preset 是刻意留的探索项，不算错）；
- 纯 `mul-left` 序列跑完后的 det 与 `det` 任务目标相符；
- 序列结果与 match-matrix 目标一致。

**它一上线就抓出一个真实的数学错误**：实验 4-4 里我把 A·B·C 算成了
`[[−1,0],[2,1]]`，实际是 `[[2,−1],[2,0]]`。这种错误靠肉眼看关卡是发现不了的，
因为页面上显示的矩阵"看起来"完全正常——只是任务永远判不过。

冒烟测试覆盖：控制台零报错、DOM 渲染、画布几何与 DPR 适配、

## 七、已知限制

1. **只有 2×2 与 3×3**，没有 n 维与抽象向量空间；也没有计算训练（高斯消元、n 阶行列式展开）与证明。
   这两块是现有「线代学习站」讲义层的优势，本实验台是补充直觉层，不替代它。
2. **3D 拖拽是「屏幕平面增量」，不是真正的空间射线解算**。够用，但在极端视角下会感觉不跟手。
3. **判题类型 15 种**，但还没有「画一条线」「输入一个数」这类自由作答的题型。
4. **无错题本 / 无章末测验**，只有关卡内的即时判定。
5. **无 i18n**：只有中文。
6. **手机端未适配**：窄屏有降级布局，但没有针对触摸手势单独优化。
7. **进度只存 localStorage**，没有账号与云端同步（原型阶段不需要）。
8. **第 8、11、12 章还没有内容**，虽然它们需要的引擎能力（`basisCoords` /
   `numLine` + `oneDim` / `cross`）本轮已经做完，但还没有实验在用，
   所以要等第 3、4 轮才有真实用例来检验这几块渲染。

### 工程教训（三轮累积）

本轮我为了给实验重排序，写了一个按行号切片重排 `lab-data.js` 的脚本，
结果**块边界算错、把文件写坏了，而且当时没有先备份**，最后只能整份重写。
代价是多花了将近一轮的时间。

教训有两条，已经落到流程里：

1. **改数据文件前先 `cp` 一份带时间戳的备份**（`tools/` 里的脚本一律当作会写坏文件来对待）；
2. 与其用行号切片，不如**先用 `check-lab.py` 校验、再让脚本按 id 重排**，
   并且重排脚本必须自己断言「每个块以 `{` 开头、以 `},` 结尾」。

好的一面是：这份文件最后是完整重写过的，格式比之前更规范
（辨析题的正解位置、解释前缀都统一了），校验器也比之前严格得多。

**第 2 轮又踩了两个坑，都已固化成工具：**

1. **统一正解位置反而制造了新规律。** 上一轮为了防「位置规律」，
   把所有辨析题的正解都挪到第 3 位；结果 33 道题里 28 道正解在第 3 位，
   「永远选第 3 个」又成了一个更容易被利用的规律。
   → 新增 `tools/balance-choices.py`，把正解均匀分布到 3 个位置
   （当前 9 / 11 / 12），并同步旋转 `options` 与 `explains` 保证一一对应。
   写这个工具时还把旋转方向搞反过一次（`(cur + k) % n` 应为 `(cur − k) % n`），
   靠 `check-lab.py` 的「以 ✓ 开头的恰好一条」断言当场抓住。

2. **手算矩阵乘法会错。** 实验 4-4 里我把 A·B·C 写成了 `[[−1,0],[2,1]]`，
   实际是 `[[2,−1],[2,0]]`。页面上矩阵显示得好好的，所以肉眼审查根本看不出来，
   但那个任务永远不会通过。
   → 新增 `tools/verify-actions.mjs`，把工具栏动作序列在真实浏览器里用真实
   `Mat` 复算一遍，再和任务里写的目标比对。

**第 3 轮又抓到四类错误，其中两个是引擎 bug：**

3. **`collinear` / `eigen` 把「反向共线」判成不共线。**
   它们用 `angleBetweenDeg(v, Av) <= 4` 判共线，但反平行的向量夹角是 **180°**，
   于是 λ = −1 这种完全合法的特征方向永远判不过。
   修法是用 `min(ang, 180 − ang)` 折回 0° 再比。
   ——这是 9-2 那道「找出 λ = −1 的方向」任务暴露出来的：
   **它本来是个不可能完成的任务**，而页面上一切看起来都正常。

4. **balance-choices 的旋转方向第二次写反。**
   `k_rot = (target − cur) % n` 才对（要让原下标 cur 落到 target）。
   我写成了 `(target − cur)`，结果分布从 28/3/2 变成 30/8/6，反而更集中。
   这次在工具里加了断言：旋转后 `new_correct` 必须等于 `target`，
   且该位置的解释必须以 `✓` 开头，否则当场报错。

5. **「无穷多解」那道题的矩阵选错了。**
   我原本用 A = [[1,1],[2,2]] 配 b = (2,2)，但列空间是 (1,2) 方向，
   b 根本拼不出来——那是「无解」而不是「无穷多解」。
   被 `check-lab.py` 的可达性检查（比较 rank(A) 与 rank([A|b])）当场拦下。

6. **balance 工具漏数了一道题。** 它按「遇到 id 行才记录当前实验」的方式扫描，
   而 2-3 里有两道辨析题，扫完第一道就把实验名清空，第二道被跳过。
   改成「先按 id 行切出每个实验的行区间，再在区间内找题目」。

**第 4 轮（第 11–12 章）抓到的：**

7. **校验器白名单漏登记了 4 个判题类型**（`dot` / `cross-mag` / `cross-dir` / `in-basis`）。
   `engine.js` 里早就实现了这些 case，但我每次加类型时只改引擎、忘了同步白名单，
   于是新写的关卡一上线就被自己的校验器判为「类型不在白名单内」。
   ——这属于**校验器与引擎不同步**，现在成了加类型时的固定检查项。

8. **`vector-angle` 的 unit 约束不生效**：`unit: true` 要求两个向量都是单位向量，
   否则即使夹角对了也不判过。这是设计意图，但我在 smoke 里一开始把它当成 bug，
   后来用「同一组向量在 `unit:false` 下判过、`unit:true` 下判不过」这条断言把语义钉死。

**现在的验收是三件套**，缺一不可：

```bash
python3 tools/check-lab.py     # 数据 + 教学层（可达性 / 唯一性）+ 指纹 / 主题 token
node tools/verify-actions.mjs   # 工具栏动作序列的矩阵复算
node tools/smoke.mjs            # 真实交互、渲染、判题器抽查
node tools/verify-themes.mjs    # 8 个主题组合的对比度（真实像素采样）
node tools/verify-links.js     # 两站互跳（hash 路由 + 讲义锚点）
node tools/shots.mjs            # 逐关截图；加 --themes 则每套主题各截一张
```

这四道里，**每一道都真实抓到过问题**：

| 校验 | 抓到的真实错误 |
|---|---|
| `check-lab.py` | 顶栏数字与实际实验数不符；`in-basis` 漏登记白名单；「无穷多解」那道题 b 不在列空间里 |
| `verify-actions.mjs` | 4-4 的 A·B·C 手算错误（`[[−1,0],[2,1]]` 应为 `[[2,−1],[2,0]]`） |
| `smoke.mjs` | `collinear`/`eigen` 把反向共线判成不共线（λ = −1 的任务不可完成） |
| `shots.mjs` | 7-3 的列空间/零空间提示文字压在 y 轴标记上 |

第 4 轮另外发现：**校验器的判题类型白名单与 `engine.js` 的 case 容易不同步**。
现在加判题类型的固定流程是「引擎 case → 白名单 → 教学层校验 → smoke 断言」四步缺一不可。

### 改了 JS 却「没生效」：缓存击穿

本页用 9 个普通 `<script src="assets/js/xxx.js">` 同步加载，**URL 永远不变**。
浏览器（尤其本地静态服务或 `file://`）不会主动重新下载没变过的 URL，
于是会出现一种很像 bug 的现象：

> 代码在磁盘上已经改对了，你刷新后跑的却还是旧版，任务始终不打勾。

**这个坑真实发生过**：6-2 的 `try-inverse` 修好之后仍然「点不动」，
排查了半天才发现浏览器一直在跑缓存里的旧 `engine.js`。

现在 `index.html` 的资源引用都带内容指纹：

```html
<script src="assets/js/engine.js?v=35ff6e4e"></script>
```

指纹由 `tools/加缓存版本.py` 按所有 js/css 的内容算出来。**内容一变指纹就变，
URL 就变，浏览器必然重新下载**；内容没变则 URL 不变，照旧走缓存。
不需要构建工具，也不用记着手动改版本号。

- 改了 js/css 之后跑一次：`python3 tools/加缓存版本.py`
- 忘了跑也没关系：`tools/check-lab.py` 会报「资源指纹已过期」
- 只想检查不写入：`python3 tools/加缓存版本.py --check`

### 关于「按钮点了没反应」这类 bug

第 6-2 关的「点击试着求 A⁻¹」一度**点多少次都不打勾**，但界面一切正常：
提示弹出来了、日志也看得见，只有那条任务始终不完成。

根因：`try-inverse` 是 20 个动作里**唯一一个忘了调用 `logAction`** 的。
而 `actions` 型任务正是拿 `App.actionLog` 判定的，所以它永远判不过。

现在有两道校验守着它：

| 校验 | 查什么 |
|---|---|
| `tools/check-lab.py` | 每个 `actions` 任务引用的日志名，必须真的存在于某个工具栏按钮上 |
| `tools/verify-actions.mjs` | 在浏览器里把**每个被任务依赖的按钮**都点一遍，确认日志真的增长；再把每关所有按钮点完，确认该关的 `actions` 任务全部通过 |

两条都是回归测试的一部分。把 `try-inverse` 的 `logAction` 再去掉一次，
`verify-actions.mjs` 会立刻报「6-2 的按钮 try-inv 被任务依赖，但点了不写日志」。
